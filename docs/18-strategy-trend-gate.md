遵循用户要求，每次只交付一个小步骤。本次在已有趋势命令中增加可选的`--strategy-check`，只回答：**截至报告最后一个完整交易日，主趋势是否满足STR-01核心普通股顺势回调的趋势门槛？**

## 本步规则

读取富途方法的`trend_latest`主趋势，不能直接拿原始绿/红色带或图标作为策略结果。

| 主趋势状态 | 趋势门槛结果 | 含义 |
| --- | --- | --- |
| 上涨有效或上涨恢复，CONFIRMED | PASS / 趋势门槛通过 | 可以继续检查其他策略条件 |
| 上涨回踩、转弱或动能不明确，CHALLENGED | WAIT / 等待 | 等待企稳及主趋势恢复 |
| 无当前方向，PENDING | WAIT / 等待 | 历史上涨不能冒充当前有效上涨 |
| 下降有效、恢复或反抽受挑战 | FAIL / 趋势门槛不通过 | 不进入核心顺势回调的后续判断 |
| 已确认震荡 | FAIL / 趋势门槛不通过 | 本模板要求上涨；富途方法目前尚不生成震荡结论 |
| 主趋势关闭/缺失、数据不足/过期、日期冲突、来源警告或状态组合不识别 | UNKNOWN / 无法判断 | 保留原因，不默认通过 |

回踩阶段仍可人工研究，但本步不宣称已满足企稳条件。该检查也不是持仓退出规则。

本步未检查普通股类型、基础可交易性、基本面、周线背景、市场环境、支撑与企稳、入场价格、压力空间、事件或账户风险。即使PASS，完整适用性及形态仍为`NOT_EVALUATED`，`strategy_ready`、`buy_signal`、`new_risk_allowed`始终为false。

## 用户运行方式

在项目根目录执行；使用虚拟环境内的完整入口避免PATH未激活：

```bash
.venv/bin/stock-trend AAPL --method futu-macd --start 2026-03-01 --strategy-check
```

结果末尾增加中文检查结果、原因及后续未检查项目。日志仍输出控制台stderr。该参数目前只支持富途方法及其历史分段模式，其他方法会提示参数错误。

需要核对某个历史截止日时，追加`--end YYYY-MM-DD`；实际判断日以`actual_end`为准。日期落在休市日时使用此前最后完整交易日，行情未覆盖请求范围时给出警告，本步返回UNKNOWN。没有指定终点时也只是检查本地档案最后完整日，**未检查档案是否足够新，不能当成今日交易许可**。

需要完整JSON时：

```bash
.venv/bin/stock-trend AAPL --method futu-macd --start 2026-03-01 --strategy-check --json --output data/AAPL-strategy-trend-gate-20261026.json
```

文件已存在时请更换文件名。JSON新增`strategy_check`，保留检查算法版本、趋势快照ID/版本、截止日期、原趋势状态、判断原因及未检查清单。退出码仍表示命令执行情况，0不代表趋势门槛通过；应读取`strategy_check.trend_gate_status`。

## 数据与边界

公共函数为`stock_research.strategy_checks.evaluate_str01_trend_gate`，只读取传入趋势报告，不联网、不调用DeepSeek、不读写数据库、不重算趋势。命令自身仍沿用原有行情/趋势缓存逻辑，缺少行情时可获取行情；本参数不改变该行为。

添加`--cached`可只读匹配当前窗口、算法及配置的已保存趋势；不存在匹配结果时提示先去掉该参数计算。新增检查在内存中派生，可随CLI报告导出，不写回原趋势快照，不新增数据库表、交易或观察池记录。不带`--strategy-check`时保持原输出。

## 用户核对清单

1. 先核对结果截止日和主趋势，再核对门槛映射是否符合上表。
2. 分别选取上涨有效、上涨回踩/转弱、下降、待确认日期；候选方向或短暂反抽不应误判PASS。
3. 数据不足、主趋势关闭或覆盖警告不能判PASS；结果应解释具体原因。
4. PASS也不能出现买入信号、完整策略就绪、仓位建议或自动加入观察池。
5. 原始色带、信号和主趋势计算不因该参数改变；普通查询不应调用财报或DeepSeek。

这些是用户验收清单，尚无运行结论。用户验证本步后，再讨论和实现下一个小条件，不一次完成整个策略模块。
