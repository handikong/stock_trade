2026-11-05可通过[指数流动性导入](39-index-universe.md)扩充同一关注列表；任务不再限于MG7。06:00捕获当时活动名单，新增成员取得完整研究/策略日线；07:00等行情阶段结束再用当次名单与有效缓存扫描。导入用的20日流动性快照不冒充策略市场缓存；06:00之后新增的成员等下一个处理周期。指数来源更新与重新筛选仍需显式命令，本轮没有增加新的自动指数同步日程。

2026-11-05。用户明确要求北京时间每日06:00更新关注列表日K并入缓存，07:00等更新结束后计算策略买点，有买点则研究并发飞书；暂不考虑账户金额。用户确认选择“股票系统后台运行”，不依赖Codex打开，不创建Codex定时聊天或机器上的另一套cron。

本轮交付代码及启用配置，未启动/重启服务、构建容器、初始化数据库、执行CLI/测试/真实行情/模型/群投递。服务需要由用户重启并保持常驻才会生效，不把配置enabled等同已运行或验收通过。

## 时间及配置

配置[post-close-schedule.json](../config/post-close-schedule.json)，路径可用`POST_CLOSE_SCHEDULE_FILE`覆盖：

| 配置 | 初值及语义 |
| --- | --- |
| enabled | true，用户已授权未来定时发送真实当前买点；false阻止后续计划执行及投递 |
| timezone | Asia/Shanghai，与运行服务器系统时区无关 |
| start_date | 2026-11-06，从用户提出需求的次日起启用，不为11月5日补发 |
| market_time | 06:00，入队关注列表行情更新 |
| signal_time | 07:00，行情更新阶段结束后入队策略及通知 |
| catch_up_until | 10:00，可改；服务短暂停机可在当日窗口补跑，10:00起不补发，防止很晚启动突然追发 |
| poll_seconds | 30，可设5—300秒；到点轮询入队，实际启动还受正在执行的后台任务影响 |
| volume_top50_enabled | 仓库配置为true，启动06:00行情任务前置的美股成交量榜扩池；旧自定义配置缺字段默认false |

必须满足行情时间＜策略时间＜当日补跑截止。配置不包含资金、收益率或自动下单参数。已入队任务保存当次配置和股票名单，修改配置不重写历史；enabled及当前窗口在每股更新/投递前重新检查。修改已完成/失败任务的时间不会创建当天第二份任务，次日按新配置执行。

按XNYS实际收盘日期及原`post_close_delay_minutes`判断最新完整交易日，再将收盘时刻转到计划时区。只有收盘落在本地当天才是本次目标：北京时间周六处理美股周五，周日/周一通常没有新收盘而跳过，节假日/提前收盘同样按交易所日历，不硬编码中国工作日或美股夏冬令收盘小时。所谓“今日K线”是最近已收盘的美股交易日，不是强行写中国日期。

默认2026-11-06早上处理2026-11-05美股收盘。服务器关机、休眠、网络断开不会被本系统唤醒；持续停机超过当日窗口时不回补那一天的买点。

## 06:00：更新关注列表日线

读取已有活动`WatchlistEntry`，不初始化MG7，不把持仓或所有研究证券作为名单。空名单只记录日志，不请求行情。每个交易日一次，创建`scheduled_market` Job，保存当时名单、目标交易日及配置。

逐只调用原`market.refresh_market`，有效完整缓存可复用，否则获取yfinance日线并增量保存；沿用复权/缺失/限流冷却和原技术支撑压力计算，不强制重取全部历史、不查询身份或财报。每只处理后立即保存状态、行情快照ID、实际日期及警告；失败保留旧缓存并继续其他股票，不无限重试、不绕过冷却。

只支持美股。处理期间已移出的成员跳过，06:00以后新加入成员留到下个批次，不静默扩展已经保存的名单。

## 07:00：缓存扫描 → 研究 → 飞书

同交易日行情Job未结束时不提前执行。后台使用同一串行Worker；如果06:00更新延迟至07:00以后，更新结束后才计算，不开另一个并行线程抢跑。补跑截止仍生效。

逐只验证当时名单中仍关注的股票：最新行情fresh、expected_session及last_complete_session等于本次目标，确有目标日complete日线。失败/旧行情/缺目标日股票明确跳过；若用户已手动补齐有效同日缓存可使用。没有可用股票不扫描、不发送。

`watchlist.scan(symbols=可用成员, offline=True)`只扫描活动名单子集，复用原色带、EMA回踩、MACD图标1及共同退出计算/归档；不联网补行情，不修改策略。扫描前被移出的股票排除并记录，不能借子集扫描引入池外股票。实际完成扫描ID先存回计划Job，再进入外部投递，重启不会因丢失扫描引用而反复重扫/乱配事件。

- 本次自动投递仅`BUY`。扫描仍可归档退出/预警，但本任务不自动发它们；原CLI完整信号通知的退出优先行为保持。
- 有当天有效买点才调用现有`notifications.run(scan_id=..., buy_only=True, send=True)`；使用扫描已有证据，不重扫。
- 第一模块读取本人已确认EPS/PE及技术结果，确定性计算和组织[五项简洁卡片](37-feishu-brief-card.md)。缺少基本面仍注明待录入/待复核，不伪装基本面通过，不恢复财报/电话会议/PE来源/DeepSeek请求。
- 无买点不调用飞书，也不发送手动research-only快照或“无信号”消息；不要求机器人配置才能记录一轮无买点扫描。
- 发送前后沿用现有行情/日期/算法/策略配置/活动成员校验，并在准备每条、真正发送前再次检查计划开关和时段。没有账户金额、现金、持仓规模、预算或自动成交操作；提醒仍由用户手动决策。
- 沿用正式SignalDelivery目标/股票/策略/信号日去重，手动命令已经发送过的不重复。失败/未知不自动重发，数量上限仍遵守FEISHU_MAX_MESSAGES_PER_RUN，延期/未知/失败在任务状态和日志中列出。

## 队列、重启与可追溯性

使用已有`research_jobs`表，不另加进程内定时队列或临时文件当任务事实。Job ID按计划/阶段/目标交易日确定，完成记录永久防止同日重复入队；active_key阻止同阶段跨交易日重叠占用。重复tick不会多建第二份任务。

Worker启动先取得`DATA_DIR/background-worker.lock`本机排他锁，避免两个本机服务同时恢复/消费任务；只允许一个Python进程，跨主机多副本不在支持范围。

普通中断任务维持原失败策略；盘后running任务重启后回queued，行情复用逐股进度，策略复用已存scan_id。只有仍处于本地同一天/同一目标交易日/有效窗口才续跑；超过窗口标failed/expired，不发送旧买点。已正常结束的partial/failed任务不会被每30秒反复重试，需人工处理资料或等下个交易日。

消息发送仍先写SENDING；进程中断时下次通知流程将残留SENDING转UNKNOWN，不自动重发。SENT跳过，其他尚未发送的事件继续处理。未取得业务接收确认不能称已送达，不能承诺飞书已读或实际成交。扫描完成但发送报错时保留扫描ID和已保存进度；本地卡片版本/研究及通知档案保持。

## 用户启动及查看

Linux 服务器可用 [`bash deploy.sh`](41-linux-deploy.md) 拉取、安装、初始化及重启。下面的命令适合单独前台启动；同一数据目录不要同时启动两套后台。

先停止旧后台进程，再在项目根目录启动并常驻：

```bash
.venv/bin/python -m uvicorn stock_research.api:app --host 127.0.0.1 --port 8000 --workers 1
```

日志实时在服务端控制台输出入队、逐股行情、扫描/推送及结束/警告。现有Compose的worker设置restart:unless-stopped，使用Compose部署则由用户重新构建/启动新镜像使新版代码生效；只重启旧镜像不会带入新Python文件。此轮没有替用户启动任何服务或系统守护进程。

无需重装入口即可用模块查看：

```bash
.venv/bin/python -m stock_research.schedule_cli status
.venv/bin/python -m stock_research.schedule_cli status --json
```

status只读配置及已有Job，不创建不存在的SQLite库，不启动Worker、不触发抓取/投递。JSON含每轮警告，配置enabled不表示进程确实存活。也可读取同源鉴权接口GET `/api/v1/schedule`，返回一样的状态。

提供`tick`给用户需要时按真实当前时间手动入队：

```bash
.venv/bin/python -m stock_research.schedule_cli tick
```

tick会按需初始化存储、只创建当前应到期Job，不立即跑网络/群消息，但常驻Worker可能随后消费。不能用它强行绕过时间、开始日期、依赖或同日去重。pyproject已登记`stock-schedule`；当前未执行安装，模块命令不依赖新入口文件。
