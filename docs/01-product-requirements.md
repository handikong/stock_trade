# 产品需求与痛点映射

版本：v0.1；记录日期：2026-10-23；状态：实现设计基线，策略效果尚未验证。

## 1. 产品目标

建立单用户的美股/ETF 决策支持系统，使每笔交易形成“研究依据 → 盘后计划 → 仓位核算 → 条件提醒 → 人工执行 → 真实成交核对 → 复盘”的闭环。优先改善执行一致性和风险透明度，收益通过实际数据评估。

用户具备 Go、Python、服务器、数据库与 AI API 使用能力。界面中文优先；证券标识保留原始代码；不依赖持续盯盘。

## 2. 已确认与未确认

| 项目 | 当前信息 | 系统处理 |
| --- | --- | --- |
| 资金规模 | 由使用者配置；未配置时不推定币种 | 初始设置草稿；参考本金与实际净值分别存储 |
| 市场 | 美股，接受 ETF | 建立普通股、普通 ETF 的独立筛选档案 |
| 风险偏好 | 本金最多亏损约 5%，允许利润回撤 | 默认草稿选本金保护，最高净值回撤保护可选 |
| 机动资金 | 希望约 10% 可抄底/波段 | 可配置预算上限，非必须使用的额度 |
| 持有时间 | 基本面可长期；机动约一个月 | 长期按逻辑检查，机动有到期规则 |
| 收益希望 | 每年约 15% | 评估目标，无保证，不触发加仓 |
| 工作模式 | 盘后为主，盘中可提醒 | 盘后形成计划，下一适用交易时段执行 |
| 已有持仓 | 后续导入 | 提供导入、对账、风险评估和逐笔迁移流程 |
| 可调性 | 参数由用户设置 | 配置版本、生效时间、变更影响预览 |

账户币种、资金使用期限、券商、数据源预算、通知渠道与策略数值参数在首次启用时填写。当前设计与开发不需要反复向用户追问这些信息。

本轮补充：首个可独立实现模块为 [个股研究](07-stock-research-module.md)。用户要求近一年K线及缓存、技术支撑压力、最新财报与电话会议保存、财报前瞻、EPS及DCF一年估值情景。它可先于账户模块交付，但不能宣称已经完成交易闭环。

第二产品模块明确为 [趋势、策略与动态观察池](08-trend-strategy-module.md)：输入股票判断趋势，适配策略，持续跟踪机会。一个逻辑主池提供多维筛选；趋势变化重评策略与计划，已有持仓保留独立管理。

## 3. 六个痛点的处理

| 编号 | 痛点 | 必须提供的能力 | 如何判断有改善 |
| --- | --- | --- | --- |
| P1 | 下降趋势抄底，亏损割肉换股 | 主账户趋势入场门槛；机动左侧策略独立预算；禁止无依据摊平；止损后冷静期和换股校验 | 无计划抄底/加仓次数，止损后冲动换股率，机动资金是否越界 |
| P2 | 上涨时小赚就走 | 入场前确定持有和退出规则；长期逻辑与机动止盈分别管理；展示“继续持有依据” | 计划外盈利退出率，盈利交易持有期，规则退出与实际退出偏差 |
| P3 | 年度收益不理想 | 扣成本绩效、现金流校正、基准比较、策略分账和行为归因 | 实际收益/回撤/成本、与基准差异；不将年度 15% 当验收承诺 |
| P4 | 盘中无目的买卖 | 下一交易日计划列表、有效期、最高接受价格；无计划开仓不能被系统标记为合规 | 计划覆盖率、违规换股率、盘中改规则次数 |
| P5 | 热门股发现迟，不敢追 | 基于可解释相对强弱和行业扩散的候选雷达；观察→准备→触发→过期；区分强势与过热 | 候选首次发现到触发的时间、晚追次数、跳过过热候选的执行情况 |
| P6 | 偏好左侧，缺少基本面和价格区间理解 | 研究卡、支撑压力区间依据、右侧回调模板、小额机动左侧模板、失效说明 | 每笔计划依据完整度、假突破损失、规则内右侧交易执行率 |

核心原则：不把“跌很多”当便宜、不把“赚一点”当卖出理由、不因错过行情而提高买入上限、不因亏损而更换策略标签。

## 4. 用户工作流程

### 首次设置与已有持仓

1. 填写账户币种、风险参考本金及其生效日，导入现金、持仓和可获得的历史成交。
2. 区分实际账户净值、券商成本基础、用户风险本金；三者不能互相替代。
3. 核对股票数量、现金、计价币种、费用和历史数据完整度。
4. 逐笔标记为长期、机动或待分类；待分类也计入总风险。
5. 输出“符合规则、需要补充依据、超额/数据不足”清单和调整草稿。已有持仓不因不符合新入场条件而自动被视为立即卖出；触及账户风险条件则另行提示。
6. 预览并激活配置。记录基准日之前的损益是已知、未知还是仅有快照，禁止编造历史收益。

### 每个交易日盘后

1. 获取完整的常规交易时段日线、企业行动、财报/公告和持仓账本。
2. 先评估持仓和账户风险，再找新机会。
3. 展示每只持仓的继续持有依据、逻辑变化、风险退出参考与下次复查日期。
4. 更新候选池；只为有策略条件、有价格区间、有风险空间的候选生成计划草稿。
5. 用户选择关注或准备执行的计划；系统预约资金和风险，展示多计划同时触发时的优先级。
6. 完整日线形成的信号最早用于之后的交易时段，不回填为当天收盘前已知。

### 盘中

只推送已登记条件触发、已有持仓风险、重要已核验事件、数据中断/恢复等提醒。提醒须显示行情时点和计划版本，不能把昨日价当实时价。新发现的热点默认加入下一次盘后研究队列。

计划外减仓允许记录；计划外开仓可以如实导入，但标记为偏离规则，不能伪造一张早于成交的计划。

### 每周与每月

- 每周：检查长期逻辑、行业/ETF 重叠暴露、即将到期的机动仓位和规则执行。
- 每月：展示各资金池的扣费绩效、交易次数、计划外行为、盈利退出偏差、亏损后换股等归因。
- 策略调参作为新版本研究，不能因为最近几笔亏损就追溯改写历史规则。

## 5. 第一版页面

| 页面 | 必要信息/操作 |
| --- | --- |
| 总览 | 净值、参考本金、风险预算余量、现金、各资金池占用、数据状态、今日允许的动作 |
| 持仓 | 导入持仓、研究依据、有效退出规则、风险贡献、行业重叠、继续持有/复查/退出原因 |
| 候选雷达 | 首次发现日期、相对强弱、行业背景、质量筛选、过热/财报风险、尚未满足的条件 |
| 趋势与观察池 | 日线/周线趋势、判断状态、独立策略机会、等待条件、变化历史；按趋势/策略/准备状态筛选 |
| 个股/ETF 研究 | 后台K线与缓存状态（前端不绘图）、支撑压力、财报前瞻、电话会正文/Q&A、指引变化、EPS/DCF适用情景、原始证据；ETF使用适用档案 |
| 交易计划 | 入场区间、失效价、数量、资金池、持有/退出规则、有效期、版本和执行核对 |
| 复盘 | 按真实成交统计，区分策略表现与执行偏差，支持用户补充交易原因 |
| 设置与审计 | 可调参数、生效时间、修改前后影响、数据源、通知、配置/计划历史 |

界面应直接解释“为什么可以买/为什么暂时不满足/为什么继续持有”，不能仅给一个不透明的 AI 分数。技术细节放详情中，主界面突出下一步行动和依据。

## 6. 范围

第一版必须覆盖：第一模块研究、第二模块趋势/策略/观察池、配置、导入、账户与资金池风控、持仓管理、候选发现、核心普通股回调/核心普通ETF回调/机动左侧修复/机动震荡区间四个策略模板、计划、盘后任务、盘中条件提醒、成交核对、基础复盘、与在线规则一致的研究回放。

暂不实现自动下单、杠杆融资、卖空、期权、高频交易、社交跟单和多用户平台。复杂突破策略、自动投资组合优化与税务优化留作扩展；CSV 费用/税费记录不因此省略。

完成第一版意味着闭环能力可验证，不意味着交易策略已有盈利优势、能够固定获得 15%，或能保证实际亏损不越过设置的本金保护线。
