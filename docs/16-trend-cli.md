## 1. 使用方式

已有项目虚拟环境和editable安装时，可直接使用新增Python模块，无需启动网页或worker：

```bash
.venv/bin/python -m stock_research.trend_cli AAPL \
  --history-start 2026-01-01 --start 2026-03-01
```

若需要`stock-trend`短命令，在项目根目录更新安装入口（由用户执行）：

```bash
.venv/bin/python -m pip install -e ./research
source .venv/bin/activate
stock-trend AAPL --history-start 2026-01-01 --start 2026-03-01
```

只写`--start 2026-03-01`时，预热起点默认同年1月1日。`--end`包含该日，未填写则到本地档案实际取得的最后一根完整日线。非交易日自动体现为实际首/末交易日，3月1日不是交易日时从其后第一个已有完整交易日展示。没有未来行情时不补造未来趋势。

```bash
# 固定历史观察终点
stock-trend AAPL --history-start 2026-01-01 --start 2026-03-01 --end 2026-06-30

# 保存完整JSON：日/周区间、逐日状态、特征、当时周线背景、参数及来源
stock-trend AAPL --start 2026-03-01 --json --output data/AAPL-trend-2026.json

# 只读完全匹配窗口/参数的已保存结果；没有则提示先计算，不悄悄重算
stock-trend AAPL --start 2026-03-01 --cached

# 显式同步行情后重新判断；计算仍仅使用所选历史窗口
stock-trend AAPL --start 2026-03-01 --force

# 当前时点模式：不带--start，使用标准SMA50/200模板
stock-trend AAPL

# 显式指定其他研究配置
stock-trend AAPL --start 2026-03-01 --policy config/trend-policy.json
```

将AAPL换成其他股票或ETF即可。不填写代码时会交互提示。日志带时间实时写控制台stderr，报告写stdout；`--output`不覆盖旧文件，JSON输出须同时传`--json`。

历史模式已有展示窗口行情时直接使用本地档案，不因实时行情TTL过期重新下载；缺少展示数据或显式`--force`时复用第一模块的行情获取方法，其下载深度仍由`HISTORY_YEARS`控制，但趋势计算严格裁剪到`--history-start`之后。它不获取财报、市场预期，不调用DeepSeek，也不调用第一模块的完整研究刷新。

退出码：0表示历史计算/读取完成，不代表每段都有方向；2表示来源警告、预热档案/请求终点未覆盖，或当前模式的数据不足/过期；1表示参数、配置、档案、计算或导出失败；130表示用户取消。历史样本早期周线不足会明确展示，不单独阻断日线分段。

## 2. 两套研究模板

| 参数 | 历史短样本（带--start默认） | 当前标准模板（不带--start默认） |
| --- | --- | --- |
| 配置文件 | `config/trend-short-history.json` | `config/trend-policy.json` |
| 日线快/慢均线 | SMA20 / SMA30 | SMA50 / SMA200 |
| 日线斜率观察 | 5根 | 10根 |
| 结构观察 | 最近40根内确认高低点 | 最近126根内确认高低点 |
| ER / 位移窗口 | 10根 | 20根 |
| 震荡边界观察 | 30根 | 63根 |
| 穿越快均线次数 | 最近10根至少2次 | 最近20根至少3次 |
| 日线进入确认 / 最短保持 | 3根 / 3根 | 3根 / 3根 |
| 周线均线、斜率、ER | SMA10/40、3根、10根 | 同左 |
| 周线确认 / 最短保持 | 2根 / 2根 | 同左 |

所有数值都是未验证的可修改研究模板，不是固定买卖规则。短样本结果是更短周期判断，不能称为SMA200的中长期趋势。只有1—2月数据时，无法得到40根完整周线；周线保持`INSUFFICIENT_DATA`，不会为了凑结果临时年化或缩短成另一种长期背景。

路径可通过`TREND_POLICY_FILE`、`TREND_HISTORY_POLICY_FILE`或本命令`--policy`指定。改参数形成新评估键，历史结果保留；不因参数改变改写旧结论。

ATR、拐点确认逻辑由`price_features.py`共享，与第一模块使用同一套算法。左右确认根数来自已有`PIVOT_LEFT/RIGHT`，默认3/3；ATR来自`ATR_WINDOW`，默认14。按当前周期计根数，周线的3根是3周。第一模块仅抽取共用函数，计算公式和平台取点规则未有意改变；未运行回归验证。

## 3. 判断条件

每种方向分别检验**结构、均线、持续性三族必要条件，全部通过**才形成候选；不使用AI、神秘总分或多数投票。只有一个分类满足时才有候选，多类冲突或没有一类完整满足时为待确认。

上涨进入条件：

1. 最近至少两个独立已确认高点及两个独立已确认低点，高点和低点分别抬高，每次变化都大于0.3 ATR。不同类型不能复用同一根宽幅K线充当四个独立点；同类型点间隔至少`left+right+1`根。
2. 快均线归一化斜率至少0.02 ATR/根；收盘不低于快均线，快均线不低于慢均线。
3. ER至少0.30，窗口内净上涨至少1 ATR。

下降使用对称条件：高低点均降低超过0.3 ATR，斜率不高于-0.02，收盘不高于快均线、快均线不高于慢均线，ER至少0.30且净下跌至少1 ATR。ER没有方向，必须同时检查带方向位移。

震荡独立判定：

- 从已确认高点/低点识别上/下边界，上沿至少2次、下沿至少2次独立触及；触及容差0.5 ATR，间隔至少配置值与`left+right+1`的较大者，默认7根，同一根不同时给上下沿计数。
- 区间宽度2—12 ATR；观察窗口至少90%的收盘在上下沿加0.3 ATR缓冲内，当前收盘也未有效越界。
- 快均线绝对斜率不超过0.015 ATR/根，价格多次穿越快均线，ER不高于0.25。

只有ER低、均线走平、跌幅大、价格便宜或不符合上涨，都不足以直接判震荡。

这里的震荡边界用于趋势分类，可能随新证据更新，不代替第一模块的支撑/压力强弱区间，也不构成一套固定区间买卖计划。当前均线只实现SMA，EMA等方法尚未实现。

归一化公式：

```text
均线斜率 = (SMA(t) - SMA(t-k)) / (k × ATR(t))
ER = abs(C(t) - C(t-n)) / sum(abs(C(i) - C(i-1)))
带方向位移 = (C(t) - C(t-n)) / ATR(t)
```

ER分母为0时按0处理，ATR非正/无效则数据不足。价格来自供应商调整价，数值可能与原始报价不同，报告会说明口径。

## 4. 候选、保持与切换

趋势枚举仅`UP / RANGE / DOWN`；判断状态独立为`CONFIRMED / PENDING / INSUFFICIENT_DATA / STALE`。当前没有有效方向时`current_trend=null`，上次确认趋势保留在独立字段，不能当成今天仍有效。

日线候选连续3根完整K线、周线连续2根才确认，并满足最短保持时段。重复查询不累计次数。确认日起才标上涨/下降/震荡，不回填到第一根候选或拐点发生日。

方向保持门槛比进入宽松：高低点仍顺向变化（大于0 ATR），斜率至少0.005、ER至少0.20、方向位移至少0.5 ATR，允许收盘低于/高于快均线0.5 ATR及均线关系0.5 ATR噪声。震荡保持仍要满足完整震荡条件。保持仅适用于上一根仍有效确认的方向；失效后重新恢复同方向也需候选确认，不能借“上次确认”立即复活。

保持条件失效时立即撤下当前有效方向，先进入待确认；不等到另一方向确认后才隐藏旧上涨。保护性退出不属于本轮，不受此确认期延迟。趋势确认也不授予买卖或账户风险许可。

### 4.1 待确认阶段必须解释方向证据

`PENDING`不等于一直等同一个确认计时器：可能根本没有完整候选，也可能已有候选正在累计根数。新增独立`progress`，解释已有部分证据；它不是第四种交易趋势，不改变`current_trend`和策略依赖许可。阶段从当日原有检查项派生，未新增数值阈值，也没有降低三族确认门槛。

按以下优先级解释：

1. 已确认/完整候选：显示已确认方向，或方向确认中及连续确认进度。
2. 单一方向的完整均线条件与持续性都满足：显示“上涨/下降形成中”，指出仍缺的结构条件。
3. 单一方向完整均线条件满足、无反向持续性：结构也满足时显示“上涨/下降动能减弱”，否则显示“均线偏多/偏空，持续性不足”。这只是当前检查状态，不声称已确认趋势仍有效。
4. 方向持续性满足，且快均线斜率、价格位置也满足，但快慢排列未满足：显示“向上/向下修复”。
5. 只有方向持续性明确，其他条件未齐：显示“短期上行/下行动能”，同时保留均线/结构等阻塞。ER和带方向位移必须一起满足，不能用ER单独定方向。
6. 没有明确方向持续性但震荡三族中至少两族满足：只显示“震荡证据未齐”。其余显示“证据冲突/方向不明”；多个完整分类冲突也保持方向不明。

阶段记录包含`code/label/direction`、`blocking_families`、逐条`blocking_checks`（检查编号、实际值、要求）和解释。`progress.direction`只是阶段所解释的方向，不能作为已确认趋势。区间文本展示阶段及未满足项；当前模式还显示实际值和要求，JSON保留详细阻塞证据。数据过期时撤下当前阶段，历史阶段移入`historical_assessment`。

## 5. 2026历史分段语义

1. 先裁剪到2026-01-01及之后完整日线，再按日期从前到后计算。1—2月可以预热指标、确认结构和累积状态，但不展示为3月以后的交易区间。
2. 判断3月某一天，只向分类器传入截至该日的价格前缀。拐点需当时已经具备右侧完整K线；周线按交易所日历聚合，仅在该周最后计划交易日已取得完整日线后生效，节假日短周同样处理。
3. 每天关联的周线背景只取截止当天已经完成的最近一周，不能把周五的周高低点或结论放到周一。
4. 按“当前趋势＋判断状态＋候选方向＋证据阶段＋未通过条件编号”合并连续段。阻塞检查实际数值的日常变化不单独切段；阶段或阻塞项改变时必须切段，避免一个月不同状态被压成笼统待确认。待确认/数据不足段完整保留，不用未来已知转折把这些日期改成上涨或下降。
5. 展示起点裁剪只影响可见日期；如果3月初承接2月已确认状态，标注“承接预热期”，保留窗口内原确认日。它是本次可用数据范围内观察到的确认起点，不声称是市场趋势的真实起点。
6. 区间结束日是事后汇总，不是当天提前知道未来转折；最后一段标记“观察截止”，并不表示趋势已结束。交易日/周根数与自然日分别理解。

文本输出为区间表，JSON另外保存逐日/逐周状态、关键数值、拐点确认日期、方向证据和各日当时周线背景。保存`source_market_id/version`、参数、算法和日历版本。当前数据仍为供应商现在的调整价和现在版本日历，没有历史供应商/日历公布时点档案，因此这是趋势历史重放，**不是无偏收益回测或已验证策略**。

## 6. 公共方法与持久化

当前判断：`trend.evaluate_trend(security_id, cached_only=False, policy_file=None)`。

历史分段：`trend.evaluate_timeline(security_id, history_start, start, end=None, cached_only=False, policy_file=None)`（日期参数使用关键字传入）。两者只读取第一模块行情，不自行获取来源；命令负责按需调用已有`market.refresh_market`。

复用现有Snapshot表：当前结果`kind=trend`，历史区间`kind=trend_timeline`。缓存键包含完整K线内容、参数/算法、日历版本及历史起止条件；未完成K线与仅抓取时间变化不增加确认次数。历史限定终点后的价格不参与该窗口计算和缓存键。

文件锁防止同一主机、同一DATA_DIR重复并发计算同股票；缓存命中直接返回。当前模式必须确认市场数据新鲜度，过期时撤下当前方向，只展示历史；历史固定窗口不因实时TTL过期失效，但新修订的价格/参数会得到新评估。原始数据缺口不静默补成K线或震荡，缺失预热/请求终点明确提示。

本轮未实现HTTP趋势接口、前端趋势页、独立趋势事件表/outbox、策略路由、观察池、批量扫描和通知；后续这些调用同一Python判断方法，不能另写方向公式。

## 7. 用户验收清单

- 只用2026数据，从3月展示；1—2月不进入可见区间，更早年份不参与指标。
- 固定终点到3月末与使用更长历史时，3月各日原始判断应一致；较长报告中的“区间结束”可能因后续持续而延长，但不改早期逐日标签。
- 第三根确认前保留候选；未确认拐点不提前使用；周五信息不出现在周一背景。
- 缺少结构、方向冲突为待确认；SMA预热/ATR不足、40周背景不足如实显示。
- 待确认期间能分辨短期动能、均线修复、形成中和具体阻塞项；阶段不改变严格确认标签，不作为策略放行条件。截短/追加终点不改变已出现阶段。
- 重复相同窗口和配置命中同一结果；修改配置产生新版本，`--cached`不偷偷重算。
- 行情获取失败、数据缺口、非法配置和输出文件已存在均有中文提示；原档案保留。

尚未全面运行上述验收；随后用户授权的AAPL实际运行、固定终点核对和K线检查见第9节，不能扩大为全部证券/参数的验证通过。
