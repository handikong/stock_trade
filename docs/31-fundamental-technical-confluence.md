## 1. 公共入口与数据

2026-11-03精简v2补充：见[精简EPS＋历史PE](33-compact-eps-pe.md)。同盈利口径及同分母类型的Forward PE直接计算当前前瞻估值参照，不套下方v1未来终点价格的折现过程。只有一个EPS模型，不生成DCF缺项，不自动降低共振模型数量门槛。历史TTM或其他跨期PE只输出倍数假设，不能作为同口径基本面确认。算法更新为fundamental-technical-current-research-v2，v1结果兼容。

`fundamental_technical.evaluate(market, cache, manual, profile)`为当前研究只读派生层，不联网、不写数据库、不请求模型、不改输入对象。`service.build_report`统一生成`fundamental_technical`，CLI、JSON及买点通知共用；`--details`显示全部依据。通知将该结果version加入投递档案。无新数据库表，现有研究快照/通知可保存当次结果；行情及手工记录不被改写。

必须有有效完整行情、当前技术算法及匹配最近完整日线的日期、有效本人确认手工估值、相同已知币种。行情缺失/旧、技术参数已变、估值未确认/待复核、币种冲突或配置错误时显示资料不足，不删技术结果，不补造估值。现价位于区间内、支撑/压力方向未定时，不用估值替其确认方向。

区间只比较`quote_low/quote_high`报价尺度，不直接比较Adj Close调整价；没有有效报价尺度就拒绝该区间的基本面判断。原技术role_status、strength、评分、量能和区间边界保持不变，不凭估值新建支撑压力。

## 2. 时点与模型

比较日是本次研究的当前日期，技术截至日单列，必须来自当前有效缓存的最近完整日线。手工输入及确认信息可晚于该技术收盘日，这只表示**当前取得资料与当前可用技术区间的研究对照**，不是当时收盘已知结论，不回填历史标签或回测。

### DCF

只使用当前有效手工路径计算的基础DCF每股价值，不把WACC敏感性网格当多个独立模型投票。默认资料日必须等于本次比较日；旧资料日不擅自用WACC滚动普通股股价。配置若显式允许若干天代理，则标明资料日、age_days、date_proxy和“未桥接经营变化”，不冒充已重新估计经营/资产负债。

DCF一年目标价不直接参与当前技术比较。DCF每股价值是模型假设结果，不代表该位置一定存在买单或卖单。

### EPS×PE

三情景仍由手工EPS与目标PE确定性计算。只有`technical_alignment`字段完整、引用有效，才使用手工股权年度要求收益率把未来终点股价折算到本次比较日：

`终点价格参照 = 目标EPS×PE / (1 + 股权要求收益率) ^ (实际剩余天数 / 365.25)`。

- `annual_required_return`必须0≤r＜1；不从DCF的WACC自动取数。
- `cash_flow_treatment=terminal_price_only_excluding_dividends`是本人明确采用的终点股价、不含期间分红口径。它不是公司零分红假设，也不等于总回报现值；未选择不能隐式默认。
- `source_note/source_ids`提供依据，GPT提议不等于已确认，仍走手工预览/确认版本流程。
- 保留目标日、EPS期间类型/起止、r和ACT/365.25口径。不把FY1/NTM重命名为目标TTM。
- 缺这些输入只排除EPS参与结合，仍展示原EPS目标情景；不阻止有效DCF参与。

旧手工JSON没有technical_alignment仍兼容，单独估值照常计算，综合判断明确提示缺口。新增字段不算独立可确认的估值模型，不能只靠填折算率确认空财务资料。

## 3. 每个区间的四态判断

逐一对可比情景判断，金额使用Decimal，边界相等视为落在区间内：

| 技术角色 | 情景冲突条件 | 其余情况 |
| --- | --- | --- |
| 支撑 | 估值参照＜技术区间下沿，意味着该区间相对该情景偏贵 | 区间内或上方：该情景不与支撑角色冲突 |
| 压力 | 估值参照＞技术区间上沿，意味着该区间相对该情景偏低 | 区间内或下方：该情景不与压力角色冲突 |

每模型全部不冲突→SUPPORTED估值支持；全部冲突→CONFLICT估值冲突；部分冲突→DIVERGENT情景分歧。模型之间结论不同也为情景分歧，不取平均值或强行排序消除差异。没有可比模型/方向未定/资料异常→UNKNOWN资料不足。

“估值支持”仅表示假设下与该角色不冲突，不表示全部价格位于估值区间，更不保证止跌/遇阻。模型区间是该模型全部可比情景的最小/最大值，不是统计置信区间。记录各模型冲突情景数/总数，但不是上涨、下跌或反弹概率；三种EPS情景不算三种独立估值方法。

技术候选也可显示基本面配合，但必须保留“角色未确认”，不得因此升级成有效支撑/压力。

## 4. 综合共振

只有同时满足下列条件才`confluence=true`：

1. 基本面综合为估值支持，没有被平均掉的冲突/分歧。
2. 技术区间与**所有可比模型区间**存在共同交集（含接触边界），记录交集。
3. 技术角色已确认，原技术强度达到配置门槛。
4. 可比独立模型数量达到配置门槛。

区间重合但存在分歧时，展示交集和分歧，不自动标共振。估值支持但远离模型区间时，也不标共振。没有足够模型时可显示单模型的条件判断，status=partial及excluded_models说明缺少哪一个，不冒充两个模型均通过。

共振是研究标签，不是交易许可、不触发新买点、不调整保护线或仓位、不延迟退出。自动买卖、资金风控、历史回测的策略和标签均未接入该层。

## 5. 配置、版本与展示

`config/fundamental-technical-policy.json`，可用`FUNDAMENTAL_TECHNICAL_POLICY_FILE`切换：

| 配置 | 默认 | 语义 |
| --- | --- | --- |
| version | fundamental-technical-v1 | 配置版本 |
| enabled | true | 关闭仅停综合判断，保留技术/手工估值 |
| dcf_max_age_days | 0 | DCF默认须同日；0～365可改，允许代理时明示其局限 |
| confluence_min_strength | strong | weak/medium/strong可选，不改原技术强弱 |
| confluence_min_models | 2 | 1～2可改，独立模型为EPS、DCF，不是情景数量 |

算法`fundamental-technical-current-research-v1`。输出algorithm/policy/evaluation_date/comparison_date/technical_as_of/currency、market与手工版本、可比模型/折算输入/排除原因、zone_index及原强弱/角色、四态、各模型证据、共同交集与共振标记；结果digest为version。日期/来源/配置/模型结果变化产生不同结果版本，不写回旧行情技术快照。

CLI新增“技术与基本面综合判断”表，保留原技术表和手工估值表。通知在区间后附基本面配合、共振标记及原因，说明排除模型与缺项。网页录入/展示后续开发。本次未发送通知。

`--cached`不请求来源/模型、不刷新行情或写库；综合判断是对已有资料的轻量只读派生，仍按本次比较日/配置重新检查时点，不把旧综合结论直接当今天有效。
