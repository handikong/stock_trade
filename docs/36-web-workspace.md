## 页面及操作

采用原生HTML/CSS/JavaScript，无新增前端构建依赖。Go静态入口和Python入口共用`gateway/static`。设计约定见[设计记录](../design-system/stock-trade/MASTER.md)，使用frontend-design及ui-ux-pro-max技能作参考。浅色工作台、深色导航，金额等宽，中文提示；手机改顶部导航，表格局部横向滚动。K线只在后台获取、缓存和计算。

### 持仓总览

- 用户添加美股代码、可选名称、持股数量、成本均价、备注；数量和均价必须为正，当前仅USD报价。允许零碎股，数量与价格最多12位小数，保存及汇总使用Decimal。
- 首页展示数量、成本、收盘参考、参考市值和浮盈亏，可编辑、移除。移除是软删除，保存变更快照，重新添加可恢复；不伪造卖出或已实现盈亏。
- 数据为用户维护的当前持仓快照，不是券商成交账本。均价×数量得到持仓成本；有效同币种收盘价×数量得到当前参考市值，两者相减为浮盈亏。不含现金、费用、分红或汇率，不冒充完整账户净值、收益率或风险许可，不预填个人本金。
- 有效收盘价按供应商缓存的十进制数计算，保留原精度；无效报价只将该股票标为待核对。缺少行情/币种冲突时不计算市值或盈亏；过期价格可以列为历史收盘/参考市值，当前盈亏留空。所有已录入持仓都有有效同币种收盘价时才显示总市值、汇总浮盈亏与构成占比，不将未知项目按零合计。
- 构成占比是已录入股票之间的市值构成，不是包含现金的账户总仓位。没有录入数据时显示真实空状态，无演示股票或收益。
- “更新行情”创建持久化后台任务，按实际活动持仓逐只复用/更新行情缓存；不是强制绕过限流。单只失败保留原档案，页面列出警告。添加/编辑本身不联网。
- 编辑/移除带版本校验，旧窗口不能覆盖新修改；本地文件锁串行写入。只有用户启动服务时才建立新增`manual_positions`表，不改旧表或已有研究数据。

### 扫描股票池

与`stock-watchlist`共用数据库中的活动名单。可添加、移出及重新读取。持仓名单和扫描名单互相独立；页面打开不初始化/重置MG7、不恢复已移出的股票；已有CLI名单直接可见，新库可由用户添加。

点击“开始扫描”创建后台任务，复用原`watchlist.scan`、两套独立买点及共同退出规则。默认已有日线复用、缺失补齐；勾选“扫描前更新行情”显式更新。无财报、PE来源、模型或飞书请求，扫描不会创建真实持仓或成交。排队/进行中的同类工作台任务只保留一份，新点击返回原任务。

每只股票显示最近一次参与扫描的结果，CLI只扫一只不会抹去其他成员的显示；最近扫描时间另按全局最后记录显示。表格区分当前买入/退出提示、退出预警及历史结果，可展开策略状态。新鲜度、行情快照、策略算法及当前配置全部匹配才展示当前信号，否则明确要求重新扫描；不把历史首次发现冒充当天机会。页面只传摘要，完整过程与历史仍保留在原扫描档案/CLI。

### 个股研究

输入代码查询，显示有效收盘日期/缓存状态、手工前瞻估值、技术支撑压力（强/一般/弱或待确认）、技术依据和基本面配合。缺行情时首次查询排队获取日线；已有档案先读取，用户可点击更新。过期/旧算法技术区间不作为当前结果发布。查询证券不自动加入持仓或扫描池。

EPS＋PE继续使用[七字段契约](35-manual-eps-pe.md)。页面可复制提问模板、粘贴JSON、预览、存草稿、本人确认保存，复用`manual_valuation.preview/save/read`与同一后端Decimal算法、证券锁、版本追加和预览哈希。

- 预览不保存；没有预览不能点保存。编辑原文取消旧预览，保存期间锁定输入，防止两种保存交叉提交。
- 提交预览生成的固定输入与`input_hash`，跨午夜保存不重新生成NTM期间。
- 页面重新打开时，七字段v4已保存草稿会载入编辑区并保留原预测期间；当前结果继续使用最新确认版本。没有新版草稿时给空白输入，避免把旧确认值默认当作新一年预测。
- 更新预测使用“新建输入”，清空编辑区及预览，下一次预览按本次录入日封装固定期间；已存版本保留。旧v1/v2/v3仍可被研究读取，页面不将其日期偷偷滚动成新的七字段输入。
- 默认未知盈利/PE口径仍只显示倍数假设，不因点“确认保存”就声称数字已外部核实或满足共振；行业组单独列出。ETF可查询技术，不套用公司EPS×PE录入。
- 可导出当前研究JSON，不展示K线，不恢复停用的财报、电话会、自动PE或DeepSeek操作。切换股票会丢弃过时的读取响应；每只股票的临时编辑及预览独立。

## 接口与后台任务

沿用FastAPI及同源校验。2026-11-07按用户要求移除内置访问口令与设置界面，已有 `APP_TOKEN` 不生效。当前是共享的本地个人工作台，部署仍只运行一个Python进程，不承诺跨主机文件锁或多副本任务协调。

| 接口 | 用途 |
| --- | --- |
| GET `/api/v1/workspace` | 只读持仓和扫描摘要，A股enabled=false |
| POST `/api/v1/workspace/research` | 校验美股并创建/取得研究证券档案，不抓取 |
| POST `/api/v1/holdings` | 新增/恢复持仓，拒绝重复活动记录 |
| PUT `/api/v1/holdings/{id}` | 按expected_version编辑，代码不可替换 |
| DELETE `/api/v1/holdings/{id}?version=...` | 按版本软删除，历史保留 |
| POST `/api/v1/holdings/refresh` | 排队更新活动持仓行情 |
| GET/POST `/api/v1/watchlist` | 读取/添加扫描名单 |
| DELETE `/api/v1/watchlist/{symbol}` | 移出扫描名单 |
| POST `/api/v1/watchlist/scan` | 排队扫描，refresh默认false |
| GET `/api/v1/workspace/jobs` | 最近工作台任务，不传整份扫描结果 |

研究GET、刷新、手工预览/保存、任务进度复用原接口。工作台接口拒绝六位A股代码及.SS/.SZ/.BJ后缀。当前校验是美股代码格式和已知币种，不增加证券身份查询；无行情时不保证用户输入代码实际存在。

## 用户启动

在项目根目录、沿用已安装的虚拟环境：

```bash
.venv/bin/python -m uvicorn stock_research.api:app --host 127.0.0.1 --port 8000 --workers 1
```

打开[工作台](http://127.0.0.1:8000)。如已有服务运行，先由用户停止旧服务再启动；不同时启动多个worker。无需前端npm安装或构建。Go8080入口沿用原启动方式；Go嵌入静态文件，使用旧二进制需要由用户重新构建/启动，Python直接提供最新文件。
