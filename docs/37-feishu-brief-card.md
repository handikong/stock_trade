# 飞书简洁研究卡

2026-11-05。用户反馈研究快照过长，明确要求：股票/买入策略、止损价及百分比、基本面估值、技术支撑压力、技术及基本面买入理由；随后要求查飞书支持的美观格式。本规则覆盖此前把完整研究lines塞入卡片的展示方案，不改变交易/估值/当前信号校验及去重规则。

## 官方格式依据

已查阅官方[自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)、[富文本组件说明](https://open.feishu.cn/document/feishu-cards/feishu-card-cardkit/components/markdown?lang=zh-CN)及[消息卡片内容参考](https://open.feishu.cn/document/home/interactive-session-based-robot/message-card-content-reference)。支持JSON卡片、彩色标题、Markdown加粗/换行/列表等结构化展示。自定义机器人能发送静态卡片，不需要另建应用或增加回调。

新买入及手动研究卡使用Card JSON 2.0：schema=2.0、header和body.elements；markdown组件配合hr分隔。使用单列、加粗标签/关键价格，避免手机窄屏横向表格；不堆图标、长ID、UTC时间戳及内部状态。未启动浏览器、调用飞书或运行CLI验证渲染；官方格式阅读不等于实际卡片验收。

## 固定五项

```text
股票：代码
买入策略（或“研究快照，未评估买点”）

止损位
冻结保护价（相对信号收盘的百分比）

基本面估值
保守 / 基准 / 乐观（三档、两位小数及币种）
行业参照范围（有资料才显示，单独参考）

技术面
支撑：最近一档区间（强 / 一般 / 弱 / 待确认）
压力：最近一档区间（强 / 一般 / 弱 / 待确认）

买入依据（手动快照为“研究结论”）
技术面：该策略触发的简短原因
基本面：估值支持、缺项或口径未确认的简短结论

最近完整日线日期、收盘及币种 · 人工决策
```

版本`stock-brief-card-v1`。公共`notification_cards.summarize/buy_card`用于两种模式，prepare返回brief及原完整lines/版本；不能先生成大段解释再按字符切掉重要结论。CLI兼容新body.elements和旧elements纯文本卡片。退出/预警卡继续原展示及优先次序，不强行套入买入模板。

### 数值及事实边界

- 估值取已有公共研究结果，只展示已确认有效/部分有效输入，不展示草稿为已确认；过期或冲突显示待复核。旧v1有未来目标日时保留目标日说明，不改称今日价值。DCF存在时可单列，未输入不补造。
- 历史三档与行业参照分开。两组区间不重叠时一句提示估值分歧，不把两组当作两个独立模型投票。
- 只有当前研究原有可比EPS模型存在、币种/时效满足时，v2/v4才可按现价到基准估值计算假设空间；未知盈利或PE分母只标口径待核对。不得因为现价低于未核实的目标，就编造“基本面通过”或保证买入收益。
- 支撑/压力各取原结果中最近的有效报价尺度区间，保持原强弱/角色。候选为待确认，不能为了简短变成强支撑；缺报价换算、旧行情或旧算法不发布区间，不拿调整价与报价混比较。
- 止损读取原信号冻结initial_protection_price；百分比=(保护价/信号参考价−1)×100，用Decimal计算。技术价有有效quote_conversion_factor时换为报价，百分比仍同尺度；无换算时明确“技术调整价”。不新增支撑止损、固定百分比止损或复用当前支撑改写冻结线。
- 手动research-only仍不执行买点策略，显示“未评估买点”“未生成止损”和“研究结论”，不能为凑模板捏造买入策略、止损或推荐。真实买点可说明EMA回踩确认或MACD零轴下金叉；基本面不足照实写。
- 仅模板控制Markdown；外部名称/字符串的格式控制符、标签、@及链接字符中和，不把任意材料作为飞书富文本执行。不新增AI请求。
- 编号、完整研究解释、研究来源版本和警告保存在独立研究投递档案/正式attempt_history；群消息仅简要缺项。正式SENT不因样式升级自动重发，手动快照每次显式发送仍是新编号一条。发送失败/未知/中断原规则保持。

## 用户查看新版

```bash
.venv/bin/stock-notify GOOG --research-only --refresh --send
```

去掉`--send`只查看CLI内容，加`--json`可输出卡片JSON，不请求飞书。`--refresh`沿用原行情更新语义，有效缓存可复用。此轮未执行命令、抓取、模型或实际投递，没有新增测试文件/断言脚本；只做代码逻辑审阅。
