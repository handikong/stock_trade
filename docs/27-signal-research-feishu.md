## 1. 本次闭环

`stock-notify`不带股票代码时扫描现有自选池（首次为MG7）；带代码时仅扫描指定股票，允许池外股票，保留行情/信号/扫描档案但不改变关注名单。两种范围沿用两套买点与共同退出规则，按以下顺序处理当前有效事件：

1. 跌破冻结保护线、共同确认退出：直接推送退出条件。
2. 一级/二级预警升级、退回、撤销或指标未知：直接推送预警变化。
3. 新买点：调用第一模块公共研究入口，再推送技术依据、研究摘要及资料缺口。同一股票同轮多策略只准备一次研究，两策略消息仍分别保留。

普通`stock-watchlist scan`仍只处理技术信号，不因此抓财报或调用AI。研究失败时保留技术提示，明确“研究未完成”，不包装成基本面筛选通过。没有新增一套基本面评分或自动买入门槛。

退出消息对应历史技术买点的独立跟踪，并非已核实的真实持仓。用户手动选择实盘退出；消息不生成真实成交，不写回测交易账本。现有技术跟踪首次达到退出条件后结束，用户未实际卖出的持续持仓提醒需后续持仓模块接入，不能用此次投递记录代替。

## 2. 配置与命令

在项目根目录的本地`.env`中增加以下字段；保留已有配置。独立模板见`config/feishu.env.example`，不要用模板覆盖现有`.env`。

```dotenv
FEISHU_WEBHOOK_URL=这里填写群自定义机器人的Webhook
FEISHU_SIGNING_SECRET=
FEISHU_TIMEOUT_SECONDS=15
FEISHU_MAX_MESSAGES_PER_RUN=20
```

需要`https://open.feishu.cn/open-apis/bot/v2/hook/…`形式的机器人地址，普通群分享链接不能使用。启用签名校验时填写机器人密钥；否则留空。若使用关键词安全设置，消息包含“股票”，可以将它作为关键词。IP白名单等设置由用户按运行服务器配置。

| 配置 | 语义 |
| --- | --- |
| FEISHU_WEBHOOK_URL | SecretStr，本地读取；只接受飞书官方HTTPS地址，不接受重定向、查询串或其他域名 |
| FEISHU_SIGNING_SECRET | 可选SecretStr，按飞书协议生成时间戳和HMAC签名 |
| FEISHU_TIMEOUT_SECONDS | HTTP超时，3～60秒，默认15；读超时结果保守记为UNKNOWN |
| FEISHU_MAX_MESSAGES_PER_RUN | 每次最多准备/尝试的事件数，1～100，默认20；超出标DEFERRED_LIMIT，下次仍需重新校验当前有效性 |

本机已有`.venv/bin/stock-notify`入口；其他环境用原有`pip install -e ./research`安装入口。在项目根目录运行：

```bash
# 单股更新行情并预览；不发送，研究只读缓存
.venv/bin/stock-notify NVDA --refresh

# 单股完整流程：更新行情，当前买点准备研究，再发送
.venv/bin/stock-notify NVDA --send --refresh

# 单股只用缓存预览；没有行情缓存会提示缺失
.venv/bin/stock-notify NVDA

# 单股发送时也只读已有研究
.venv/bin/stock-notify NVDA --send --cached-research

# 默认预览：仅缓存行情和研究，不发送、不调用AI
.venv/bin/stock-notify

# 显式更新行情后预览；研究仍只读缓存
.venv/bin/stock-notify --refresh

# 更新行情，当前买点补齐研究，然后发到群里
.venv/bin/stock-notify --send --refresh

# 已有新鲜行情，买点也只读取缓存研究，然后发群
.venv/bin/stock-notify --send --cached-research

# 查看投递记录
.venv/bin/stock-notify history
.venv/bin/stock-notify history --json
```

可用`--scan-id 扫描ID --send`处理已有扫描；`stock-notify NVDA --scan-id 扫描ID --send`仅筛选其中NVDA，扫描没有该股票则明确报错，不回退扫描其他股票。不带代码读取单股扫描时沿用档案中的单股范围。历史/中断扫描、过期交易日、行情修订或不匹配当前默认策略配置/算法的扫描不放行；批量模式另校验股票池成员，单股是本次显式选择、不要求成员资格。自定义策略扫描须与当前默认配置相同。`--scan-id`不能与`--refresh`一起用。`--json`输出结构化结果（含scope和symbol），预览包含完整卡片，便于用户核对。

默认预览可以没有Webhook，不写投递记录、不占用投递次数，但会按原扫描流程计算并保存本地扫描和信号历史。配置了地址却格式错误时会提示纠正。没有当前有效信号时不发送“无信号”群消息。

退出码：0表示本轮处理结束（也可能无新事件或已发送去重）；2表示旧行情/扫描警告、失败、未知、延后等需关注；1表示流程错误；130表示中断。stdout是表格/JSON，控制台进度与错误走stderr。

## 3. 第一模块如何复用

买点发送时调用`signal_research.prepare`：

- `financial_reports.process_financial_reports(force=False, analyze_reports=False)`处理/永久归档财报，不请求原文分析。
- 沿用第一模块的动态市场预期获取及确定性估值草稿计算，`build_report`组装已有数据。不会再次刷新行情替换买点的价格证据。
- `--cached-research`和所有预览只读取已有研究，不请求财报、RSS或模型。没有缓存明确标缺失；估值输入/配置不匹配时不发布旧区间。
- 不调用AI写通知文案。卡片摘录外部公开简析并附来源/时间/链接，另列财报期、财务/预期保存时间、独立估值与缺口、支撑压力；不使用旧AI档案充当当前研究。完整材料保留本地。
- 财报日历发布事件尚未接入；永久保存的财报不等于已自动覆盖最新发布财报。消息明确这一限制。当前研究不能流入历史回测作为当时可知数据。

同一事件已经SENT时先去重，再决定是否准备研究，避免重复命令引起不必要的研究请求。

## 4. 当前有效性与投递记录

仅接受非历史模式、扫描预期交易日等于交易所日历最新完整交易日、股票状态OK且当日触发的事件。日历沿用半日市/休市和配置的收盘后延迟。行情还要满足原模块TTL、覆盖及完整日线要求；旧行情不会作为新提醒补发。

研究前和HTTP投递前分别校验行情、当前配置/算法；批量另校验股票池成员状态，单股按显式选择处理。最新缓存须仍新鲜、最后完整交易日一致，且从预热起点到信号日的完整行情内容及复权口径与扫描来源相同；发生修订后应重新扫描。所有信号均为完整日线识别，不是实时盘中监控。

新增表`signal_deliveries`；由用户首次执行命令时的原初始化流程增量创建，不改既有表字段。关键口径：

- 目标用Webhook的SHA256识别，数据库、日志、JSON和异常不保存地址或签名密钥；更换目标视为不同群。
- 去重键含目标、股票、事件类型、策略、信号日、原买点日期，预警另含目标层级；同事件改参数不重复通知。范围不进主键，单股与批量共享SENT去重。不同买点同日退出分别保留。
- 本机`notifications.lock`避免本地并发；不是跨主机分布式锁。多机器共享数据库投递暂不支持。
- 发送前提交SENDING和次数，飞书HTTP成功且业务码0后记SENT。仅HTTP200不足以确认。
- 明确拒绝或无法连接记FAILED；读超时、异常响应或发送中断记UNKNOWN。下次命令将遗留SENDING转UNKNOWN，不自动重发。
- 记录每次尝试的卡片、事件、来源/研究快照ID、时间、结果和安全错误，重试保留前次attempt_history。
- 每轮批量请求间隔至少约0.65秒，减少触发官方频控的机会；共享机器人或外部程序仍可能耗尽额度，限流会记录结果，不循环重试。

`SENT`只表示接口确认接收，不表示群成员已读或交易已执行。网络中断时无法保证严格“恰好一次”，采用保守暂停重发。

确认群里没收到后，用户可显式重试仍属当前有效的事件：

```bash
.venv/bin/stock-notify --send --retry-failed
# UNKNOWN可能已经到群，先核对，再决定是否执行这条
.venv/bin/stock-notify --send --retry-unknown
```

上述重试仍受行情/日期校验约束，不补发过期买点；命令会重新准备本次卡片，旧尝试仍存档。SENT不受重试标志影响。

机器人协议、签名与频控依据：[飞书自定义机器人官方指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot?lang=zh-CN)。
